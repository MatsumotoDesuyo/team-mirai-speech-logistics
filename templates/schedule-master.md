# 司令塔シート テンプレート規約

衆 26 司令塔シートのレビューを踏まえ、**軽量化版**として今期テンプレートを定義する。場所詳細は [schedule-detail.md](./schedule-detail.md)（スケジュール検討シート）に集約し、本シートは **日別の進捗状態と AI 連携** のみを担う。

## 設計原則

1. **二重管理しない**: 場所・時間・写真等の詳細はスケジュール検討シートが単一情報源。本シートはそれらへのリンクと進捗状態のみ。
2. **AI が即読める**: ステータスは enum 化、現在の作業対象は 1 セルで明示、指示テンプレは内蔵。
3. **シート 1 枚で運用低調を脱する**: 衆 26 で運用低調だった原因（入れる動機が薄い）を解消。AI 連携の起点としての価値を持たせる。

## シート構造

### A1〜B5: メタデータブロック（候補者・選挙の情報）

| セル | 内容 | 例 |
|---|---|---|
| A1 | 候補者名 | 山田太郎 |
| B1 | 選挙種別 | 2027 統一地方選 / 東京都〇〇区議 |
| A2 | 運用開始日 | 2027-03-15 |
| B2 | 投票日 | 2027-04-23 |
| A3 | 候補者届け出日 | 2027-04-16 |
| B3 | 公示日 | 2027-04-16 |
| A4 | スケジュール検討シート URL | https://docs.google.com/spreadsheets/d/... |
| B4 | 演説場所写真 Drive | https://drive.google.com/drive/folders/... |
| A5 | 候補者の Slack / LINE チャンネル | 該当チャンネル URL |
| B5 | デザイン依頼先 | 該当 Slack チャンネル URL |

### A7〜B11: AI 連携セル

| セル | 内容 |
|---|---|
| A7 | 現在の作業対象（例: 「2027-04-18 渋谷検討中」） |
| B7 | 最終更新日時 |
| A8〜A11 | 指示テンプレ（chief-of-staff プロンプト本文の貼り付け先） |

### Row 13 以降: Schedule_Master テーブル

| 列 | 名前 | 意味 | 入力規約 |
|---|---|---|---|
| A | ID | 日付別マスター ID | `YYYY-MM-DD` 形式 |
| B | 日付 | 演説日 | `YYYY-MM-DD` |
| C | 曜日 | - | 自動算出（数式可） |
| D | エリア・テーマ | その日の演説エリア概要 | 自由テキスト |
| E | ステータス | 現在の状態 | **enum: 未着手 / ドラフト中 / 候補者承認待 / 詳細詰め / 画像発注 / 広報準備 / 完了** ([statuses.md](../knowledge/statuses.md)) |
| F | 候補者承認 | 承認状況 | enum: 未 / 申請中 / 承認済 / 差し戻し |
| G | スケジュール検討タブ | 該当タブへのリンク | スケジュール検討シートの該当タブ URL |
| H | 備考(注意点) | 特記事項 | 自由テキスト |
| I | NextAction (AI 記述用) | AI が次のアクションを書き込む | AI 書き込み欄 |
| J | NextAction 更新日時 | I 列の最終更新タイムスタンプ | AI が I 列更新時に同時更新 |

## 規約上の制約

- **E 列 ステータス**: Data Validation でドロップダウン化必須。[statuses.md](../knowledge/statuses.md) の語彙のみ。
- **F 列 候補者承認**: 同じく Data Validation でドロップダウン化。
- **G 列 スケジュール検討タブ**: 必須リンク。同じ ID（`YYYY-MM-DD`）でスケジュール検討シート側にタブが存在することが前提。
- **I 列・J 列ペア**: NextAction を更新する際は必ず両方同時更新（AI が自動で）。
- **A7 現在の作業対象**: AI セッション開始時に最初に読むセル。AI はここから「どこから話を始めるか」を判断する。

## 衆 26 からの主な差分

| 衆 26 | 今期テンプレ | 理由 |
|---|---|---|
| Schedule_Master + Location_DB の 2 テーブル | Schedule_Master のみ、Location_DB は廃止 | 場所詳細はスケジュール検討シートに集約、二重管理を排除 |
| 「全体ステータス」自由テキスト | enum 化（[statuses.md](../knowledge/statuses.md) 連動） | AI が遷移判断できる |
| メタデータなし | A1〜B5 にメタデータブロック | AI が候補者・選挙の前提を即読める |
| AI 連携セルなし | A7〜A11 に「現在の作業対象」「指示テンプレ」 | AI 連携前提の運用 |
| 「高山承認」（候補者個別） | 「候補者承認」（汎用化） | 候補者ごとに使い回せる |
| NextAction 更新タイムスタンプなし | J 列で時刻管理 | AI 書き込みのトレース性 |
