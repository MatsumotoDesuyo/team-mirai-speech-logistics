# Stage 5 模擬日程 wet test 計画

[DESIGN.md §6 / §7](../DESIGN.md) の Stage 5 を具体化した実証計画。

## 目的

- マニュアル §1〜§5 を読んだ「演説決め隊新規メンバー視点」で Phase 0〜3 に着手可能か実証する
- Stage 3 で個別シナリオを試したのに対し、Stage 5 では **1 日の完全フローを通す**
- DESIGN §7 検証計画項目のうち、模擬日程で実証可能なものを埋める

## 模擬設定

### 架空候補者

| 項目 | 値 |
|---|---|
| 候補者名 | テスト候補者A |
| 選挙 | 2027 統一地方選 / 東京都〇〇区議 |
| 選挙カー | あり |
| 体力 | 標準（45 分演説 × 6 枠程度を想定） |

### 模擬日程

| 項目 | 値 |
|---|---|
| 演説日 | 2027 年 4 月 18 日（日） |
| エリア | 渋谷駅周辺 + 新宿駅周辺 |
| 開始時刻 | 11:00 |
| マイク納め | 20:00 厳守 |

### 想定状況

- **公示日**: 2027 年 4 月 16 日（金）想定 → 4/18 は選挙運動可能日
- 候補者陣営: 経験豊富な演説決め隊メンバーが運用する想定
- LINE オプチャ: 既存（テスト候補者A のサポーター 30 人程度想定）

## 実行手順

### Phase 0: 起票（5 分）

1. テンプレ進捗管理シートを複製
   - 元: <https://docs.google.com/spreadsheets/d/1njATHzGa_nLEDW9PRbhTyBfhia2YE_94ojAEot11LT4/edit>
   - 複製後ファイル名: 「進捗管理シート_テスト候補者A」
2. テンプレスケジュール検討シートも複製
   - 元: <https://docs.google.com/spreadsheets/d/1kSrubFBiPbey7nDpI_QR23LT1AK6q7a7Qkf_DU_Bpbw/edit>
   - 複製後ファイル名: 「スケジュール検討シート_テスト候補者A」
3. 進捗管理シート A1〜D5 メタデータブロックを記入
4. Schedule_Master タブの 14 行目に `2027-04-18` を起票
   - エリア・テーマ: 「渋谷・新宿」
   - ステータス: 「未着手」→「ドラフト中」

### Phase 1: タイムライン設計（10 分）

1. Gemini Pro に chief-of-staff プロンプト + 3 つの添付を貼る
2. シナリオ S1 を投げる:
   ```
   2027 年 4 月 18 日（日）に東京〇〇区で街頭演説を 1 日入れたい。
   候補者は選挙カーあり、午前 11 時頃から夜 20 時のマイク納めまで、
   午後の渋谷駅周辺に重点を置きたい。タイムラインを設計してください。
   ```
3. AI 提案のタイムラインをスケジュール検討シートの新規タブ `2027-04-18_テスト候補者A` に転記
4. 進捗管理シートのステータス「ドラフト中」→「候補者承認待」
5. （模擬）候補者承認を仮で OK にして「詳細詰め」へ

### Phase 2: 場所詳細詰めとリスクチェック（15 分）

1. mirai-speech-spot-base UI で「渋谷区」を検索（実際の登録スポット数を確認）
2. シナリオ S2 を投げる:
   ```
   渋谷駅周辺で 45 分演説の場所を 2-3 か所検討したい。
   候補地を提案して、ロジ観点でチェックしてください。
   ```
3. AI 提案の候補を spot-base 上の実スポットと突合
4. シナリオ S3 タイプで近隣の大学・病院があれば追加リスクチェック
5. スケジュール検討シートの該当タブに spot-base URL or 場所詳細を記入

### Phase 3: 制作・告知（10 分）

1. シナリオ S4 タイプで告知文を生成（**届け出後**、選挙期間中の文面）:
   ```
   2027 年 4 月 18 日 11:00-11:45 に〇〇駅前で演説します。
   公示日（2027 年 4 月 16 日）の後で、選挙運動可能日です。
   LINE オプチャ用の告知文と、サポーター募集アンケートを作成してください。
   ```
2. AI 提案の告知文を確認、文体チェック
3. LINE オプチャアンケートの選択肢 4 つが含まれるか確認
4. 進捗管理シートのステータス「詳細詰め」→「画像発注」→「広報準備」→「完了」

### Phase 4: 振り返り（10 分）

実証で見えた発見事項を [stage5-result.md](./stage5-result.md)（新規）に記録:

- マニュアルの記述で迷った箇所
- プロンプトの応答で改善が欲しい箇所
- Phase 間の遷移で詰まった箇所
- spot-base UI の使用感
- 進捗管理シート・スケジュール検討シートの実用性
