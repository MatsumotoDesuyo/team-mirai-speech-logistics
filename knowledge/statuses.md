# ステータス定義（Schedule_Master）

司令塔シートの「Schedule_Master」シートで日程ごとに管理する状態。各ステータスは [workflow.md](./workflow.md) の Phase 0〜3 と対応する。

| ステータス | 状態 | 対応 Phase | 次のアクション |
|---|---|---|---|
| 未着手 | タスク発生前 | - | Phase 0: 司令塔シートに日程追加 |
| ドラフト中 | 地図を見ながら時間を計算中 | Phase 1 | タイムライン作成、Slack で候補者に提示 |
| 候補者承認待 | タイムライン提示済み、返答待ち | Phase 1 終 → Phase 2 並行 | Phase 2 のリサーチを並行で進める（承認待ちで止めない） |
| 詳細詰め | 具体的な駐車位置・地点を特定中 | Phase 2 | mirai-speech-spot-base 確認 → 追加調査 → 現地/Maps 確定 |
| 画像発注 | デザインチームへ依頼済み | Phase 3 | 成果物チェック、要件適合確認 |
| 広報準備 | 画像完成、文面作成済み | Phase 3 | オプチャ投稿、LINE オプチャ告知、サポーター募集 |
| 完了 | 全ての予約・告知が終了 | Phase 3 終 | 振り返り、写真 Drive アーカイブ |

## 運用上の注意

- **「候補者承認待」と「詳細詰め」は並行可能**: 承認プロセスが遅れることが多いため、承認待ちの間に Phase 2 のリサーチ（場所候補出し）を進める運用が推奨されている（衆 26 知見）。
- **ステータス遷移は一方向ではない**: 例えば「詳細詰め」で場所が確定できない場合、Phase 1 の時間割を見直し「ドラフト中」に戻すこともある。
- **完了後の振り返り**: 演説後に何が機能したか・しなかったかを mirai-speech-spot-base や次回の調整に反映する運用を想定（今期から正式化）。
